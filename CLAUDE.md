# Заметки для ИИ-агента

Читать в начале каждой сессии. Короткие факты о проекте, договорённости и решения, которые уже приняты. Новое важное — дописывать сюда (раздел «Журнал решений»), устаревшее — удалять.

## Что это

Личный ипотечный калькулятор, работает только в браузере, без бэкенда. Идея: зафиксировать все параметры сделки, кроме одного, и посчитать этот один (платёж, недостающий взнос, срок). Подробности и этапы — в `some-plan.md`.

## Где что лежит

- `some-plan.md` — план и **todo-список** (в шапке файла, поле `todos`, статусы `pending` / `in_progress` / `done`). Единственный источник правды по задачам: обновлять статусы там же, отдельных todo-файлов не заводить.
- `idea-raw-fragment.txt` — исходное описание идеи от пользователя, как есть. Не редактировать.
- `docs/research/` — исследования (рынок кредитов и т. п.), с датой в имени файла, источниками и уровнем доверия к цифрам.
- `src/domain/` — чистые расчёты без React: типы, аннуитетный график (с накопленной переплатой), суммы по годам, сумма кредита, валюты и сбережения (`money.ts`), карточки банков и проверка сделки (`products.ts`), решатель «зафиксировать всё, кроме одного» (`solver.ts`, `solveDeal`). Календарь — `calendar.ts`, хроника реального кредита — `journal.ts` (`runJournal`), «цена промедления» дополнительной суммы — `helpTiming.ts`, частный заём — `privateLoan.ts`, «досрочка или вклад» — `placement.ts`, «копить вместо кредита» — `saveInstead.ts`, аренда в прошлом — `rentHistory.ts`. Главная функция графика — `buildSchedule` (ставка по периодам, «только проценты», досрочка, тип графика `repayment`: аннуитет или дифференцированный); `buildAnnuitySchedule` — её частный случай. Тесты рядом (`*.test.ts`).
- `src/state/` — состояние приложения. `appState.ts` — формат v7 (профили → сценарии → компоненты, общие банки/курсы/СР), операции, разбор и миграция; `legacy.ts` — чтение старых версий 1–6 (не менять); `parse.ts`, `parseShared.ts` — помощники разбора; `evaluate.ts` — сборка сценария из компонентов и полный расчёт (`evaluateScenario`, `evaluateProfile`); `loans.ts` — реальные кредиты и журнал событий (хранение, разбор, вход для `runJournal`); `help.ts` — дополнительная сумма в сценарии (`evaluateHelp`); `useAppState.ts` — автосохранение в `localStorage`. Меняешь формат — поднимай `STATE_VERSION` и пиши миграцию. Стартовые карточки банков — `sampleProducts.ts`, демо для первого запуска и гостя — `demo.ts`.
- `src/ui/` — компоненты интерфейса и стили; графики (Recharts) — в `src/ui/charts/`, цвета графиков — хук `useChartColors()` в `charts/colors.ts` (светлый и тёмный наборы; проценты — оранжевый, тело долга — синий, досрочка — зелёный; цвета сценариев — фиксированный порядок, проверен валидатором палитры). Цвета интерфейса — только CSS-токены в `:root` (`styles.css`), тёмная тема — переопределение токенов. У легенд `itemSorter={null}`, иначе Recharts сортирует по алфавиту.
- `src/reference/nbrbHistory.ts` — справочные данные НБРБ (история ставки рефинансирования с 2011, официальные курсы USD/EUR по месяцам, в новых рублях); источники — `docs/research/nbrb-history-2026-11.md`. Показ — `ui/ReferenceContent.tsx`: боковая панель «Справка НБРБ» (`ReferenceDrawer`) и отдельная страница `reference.html` (вторая точка входа Vite, `src/reference/main.tsx`).
- `src/app.tsx` — сборка единственного экрана: вкладки-ракурсы (`ui/AngleTabs.tsx`) «Подбор сделки · Банки · Мой кредит · Доп. взносы · Копить · Аренда», без роутера. `src/main.tsx` — точка входа.

## Команды

- `npm install` — один раз после клонирования.
- `npm run dev` — запуск, страница на `http://localhost:5173`.
- `npm test` — тесты (vitest).
- `npm run build` — проверка типов (`tsc`) и сборка в `dist/`.

Перед коммитом прогонять `npm test` и `npm run build`.

## Договорённости

- Весь интерфейс и сообщения об ошибках — на русском. Числа форматировать через `Intl` с локалью `ru-RU` (`src/ui/format.ts`).
- Расчёты — только в `src/domain`, UI их вызывает. Любая новая формула в domain — сразу с тестом на цифрах, которые можно проверить независимо (банковские таблицы, учебные примеры).
- Деньги внутри не округляем, округление только при выводе. Исключение — хроника реального кредита (`domain/journal.ts`): там проценты округляются до копеек на каждой операции, как в выписке банка.
- Месяцы графика нумеруются с 1 (номер платежа). Календарь — только подписи: дата платежа N = дата выдачи + N месяцев (`paymentDate`, `domain/calendar.ts`); даты хранятся строкой «ГГГГ-ММ-ДД» и считаются без часовых поясов.
- Ставка хранится в % годовых (`12` = 12%), срок в домене — в месяцах.
- Некорректный ввод в domain → `RangeError` с русским текстом; UI показывает текст ошибки, а не падает.
- Без роутера, без бэкенда, без внешних API (курсы валют вводятся руками).
- Пользователь — новичок в git и облачных сессиях: объяснять шаги просто, команды давать готовыми к копированию (у пользователя Windows).

## Рабочий процесс

- Работа идёт в облачной сессии Claude Code; изменения попадают к пользователю только через push в ветку на GitHub.
- Пользователь проверяет у себя: `git fetch`, `git switch <ветка>`, `npm install`, `npm run dev`.
- Калькулятор опубликован: https://alexey0795.github.io/home-equity-blueprint/ (репозиторий публичный, Pages из GitHub Actions; каждый push в main публикует заново). В репозиторий — только код и общие данные (карточки банков); личные данные — в браузере и в JSON-файлах вне git.
- Из облачной сессии сайт `*.github.io` не открывается (сетевые настройки) — проверять публикацию по запускам workflow «Публикация на GitHub Pages» через GitHub (MCP-инструменты Actions).
- Пользователь разрешил сливать в `main` самостоятельно (единственный контрибьютор). Порядок: работа в ветке → `npm test` + `npm run build` → fast-forward в `main` → push обеих веток.
- PR открывать только по просьбе пользователя.

- 2026-11: этап 4 готов. Формат данных v4: у сценария `freeVariable` (`payment` | `downPayment` | `price` | `term` | `rate`) и `targetPayment` («Платёж не больше»). Решения:
  - «Платёж не больше» сравнивается с МАКСИМАЛЬНЫМ платежом графика (у льготных программ платёж растёт).
  - Взнос и цена — точная формула (платёж пропорционален сумме кредита); срок — двоичный поиск по целым месяцам, округление вверх; ставка — деление отрезка пополам на [0; 100]. Для карточки банка подбирается ставка рефинансирования, для ручного режима — сама ставка.
  - Вычисленное значение в состоянии не хранится. При смене свободной величины вычисленные значения записываются в сценарий (кроме подобранной СР — она общая для всех сценариев); при уходе с «Платёж» желаемый платёж = текущий макс. платёж, округлённый вверх.

- 2026-11: этап 5 готов. Формат данных v5: `prepayments` в сценарии (id, месяц, сумма, `reduceTerm` | `reducePayment`). Решения:

  - «Сократить срок»: платёж прежний, плановый последний месяц переносится ближе; дальнейшие пересчёты (смена ставки) идут на сокращённый срок. «Уменьшить платёж»: пересчёт на остаток и прежний срок. Взнос в период «только проценты» уменьшает будущий платёж (сокращать там нечего).
  - Решатель подбирает свободную величину по договору БЕЗ досрочки (`baseline`), показывается график с досрочкой. «Платёж не больше» сравнивается с максимальным платежом договора.
  - Запрет досрочки из карточки — предупреждение, взнос всё равно учитывается в расчёте.
